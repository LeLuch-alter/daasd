# STOCKROOM

Учебный интернет-магазин с временным резервированием товаров. Стек: Next.js App Router, TypeScript, Tailwind CSS, Supabase PostgreSQL, Vercel.

## Возможности

- Каталог с 14 демонстрационными товарами и ценами в тенге.
- Корзина хранится в браузере.
- Обычная и скидочная стратегии расчёта цены.
- Серверное создание заказа и атомарный резерв всех его позиций на 10 минут.
- Оплата в демонстрационном режиме: реальные деньги не списываются.
- Повторная оплата уже оплаченного заказа не списывает остатки повторно.
- Отмена освобождает резерв без списания физического остатка.
- Истёкшие резервы не считаются активными даже до фоновой очистки.

## Требования

- Node.js 20.9+.
- Проект Supabase.
- Git (для развёртывания через GitHub).

## Локальный запуск

1. Установите зависимости:

   ```bash
   npm install
   ```

2. Скопируйте `.env.example` в `.env.local`.
3. В Supabase откройте SQL Editor и выполните `supabase/migrations/001_stockroom.sql` целиком.
4. Затем выполните `supabase/seed.sql`.
5. Заполните `.env.local`:

   ```env
   NEXT_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
      SUPABASE_SERVICE_ROLE_KEY=YOUR_SERVER_ONLY_SERVICE_ROLE_KEY
   ```

6. Запустите приложение:

   ```bash
   npm run dev
   ```

7. Откройте http://localhost:3000.

Приложение не подключает Supabase напрямую из браузера. Все обращения к базе идут через серверные страницы и Route Handlers, а сервер использует service-role key. **Никогда не добавляйте `SUPABASE_SERVICE_ROLE_KEY` в переменные с префиксом `NEXT_PUBLIC_`, не отправляйте его в браузер и не коммитьте `.env.local`.**

Если переменные Supabase не настроены, главная страница покажет демонстрационный каталог для просмотра. Создать реальный заказ без настроенной базы нельзя.

## Как работает резерв

Доступное количество = физический остаток − сумма активных резервов, срок которых строго больше текущего времени PostgreSQL.

Создание заказа проверяет все позиции в одной транзакции и блокирует строки товаров и склада в стабильном порядке. Если одного товара не хватает, SQL-функция возвращает ошибку, а заказ и частичные резервы не создаются.

При оплате функция блокирует заказ и резерв, повторно проверяет срок после получения блокировок склада, уменьшает физический остаток и переводит резерв в `consumed`. Повторный запрос оплаты сериализуется блокировкой строки заказа и возвращает успех без повторного списания.

## Ручная проверка

1. Добавьте товар в корзину и оформите заказ. Убедитесь, что появился код заказа и таймер на 10 минут.
2. Откройте заказ и нажмите демонстрационную оплату. Статус должен стать `paid`.
3. Повторите POST-запрос оплаты для того же кода (через DevTools или API-клиент). Физический остаток не должен измениться второй раз.
4. Создайте другой заказ и отмените его. Резерв должен получить статус `released`, а физический остаток остаться прежним.
5. Добавьте несколько единиц товара с маленьким остатком и попробуйте оформить количество больше доступного. Заказ не должен создаться.
6. Проверьте `expires_at` у резерва в базе. После истечения оплатить его нельзя; сравнение использует `expires_at <= clock_timestamp()` как истёкший резерв.
7. В двух отдельных сессиях попробуйте одновременно зарезервировать последние доступные единицы одного товара. Успешным может быть только заказ, который укладывается в остаток.
8. Измените цену товара после создания заказа. Сумма старого заказа должна остаться прежней благодаря снимку цены в `order_items`.

Для ускоренной проверки истечения можно временно создать тестовый резерв с `expires_at = clock_timestamp() + interval '15 seconds'` в отдельной тестовой базе. Не меняйте время действующих заказов на рабочей базе.

## Проверки перед деплоем

```bash
npx tsc --noEmit
npm run build
```

Эти команды нужно выполнить в окружении с установленными зависимостями. SQL-миграция здесь подготовлена, но её выполнение в реальном проекте Supabase нужно подтвердить отдельно.

## Развёртывание на Vercel

1. Загрузите проект в GitHub.
2. Импортируйте репозиторий в Vercel.
3. В настройках проекта добавьте те же три переменные окружения.
4. Выполните Deploy.
5. После изменения переменных окружения запустите новый деплой.

## Важные ограничения учебной версии

- Оплата имитируется кнопкой, платёжный провайдер не подключён.
- Нет аккаунтов покупателей и административной панели.
- Нет автоматического фонового процесса, который меняет статус всех старых резервов на `expired`; для расчёта доступности это не требуется, поскольку срок проверяется при каждом резервировании и оплате.
- Публичный код заказа используется для доступа к странице заказа. Не публикуйте чужие коды.
